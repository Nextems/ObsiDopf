# Локальный постраничный редактор Word

DOC/DOCX редактируются в **SuperDoc 1.47.2**, встроенном через Microsoft Edge
WebView2 в WPF. Это замена прежнего RichTextBox с декоративными разрезами.
Редактор использует собственные модель документа, перенос строк/таблиц,
колонтитулы, линейку, историю отмены и виртуализированный просмотр листов.
Окно виртуализации настроено на 5 страниц с дополнительным запасом в одну.
Модель документа остаётся полной; виртуализация ограничивает отображение.

Уведомления об изменениях передаются в WPF не чаще одного раза в 150 мс во
время непрерывного набора. Первая правка после открытия/снимка отправляется
сразу, перед возвратом DOCX ожидающие уведомления сбрасываются. Это сохраняет
контроль несохранённых правок. Поиск Word не перебирает слои подсветки PDF;
неизменные счётчик страниц и масштаб повторно не отправляются. Сам движок
по-прежнему рассчитывает переносы документа; фактическое время перевёрстки
без запуска и профилирования не измерялось.

В подготовке разметки применён локальный патч `patch-engine.mjs`: вместо
повторной сериализации всех узлов документа используется `layout-performance.js`.
Неизменённые immutable-узлы ProseMirror переиспользуют JSON из WeakMap, а новые
узлы на пути правки сериализуются заново. Корневые свойства секции берутся из
текущего converter, а сериализация экспорта и буфера обмена не меняется.
Патч применяется при сборке только к известному SHA-256 пакета 1.47.2.
Тот же файл добавляет LRU-кеш на 4096 измерений Canvas текста; ключ включает
шрифт, интервалы, направление, выравнивание и базовую линию. Загрузка шрифтов
сбрасывает кеш. Это сокращает повторную подготовительную работу, но не
заменяет полноценную пагинацию с проверкой переносов и сходимости. Без
профилирования нельзя утверждать, что именно этот этап определяет задержку.

Диагностика теперь выключена по умолчанию. Для включения нужно запустить
приложение с переменной `OBSIDOPF_PROFILE_LAYOUT=1`.
Для диагностики замеряются шесть существующих этапов движка: getJSON,
buildPositionMapFromPmDoc, toFlowBlocks, incrementalLayout, painter.paint и
painter.postPaint. Последние 60 записей сохраняются локально в
`%LOCALAPPDATA%/ObsidianDocs/Diagnostics/word-layout-*.json` с задержкой 1,5 с
и записью в фоновом потоке. Отчёт содержит времена, счётчики кеша и число
страниц; текста, имён документов и содержимого в нём нет. Наличие этих
отчётов не означает, что задержка устранена. Данные никуда не отправляются.

Сохранение получает DOCX непосредственно из работающего редактора. Экспорт PDF
по-прежнему выполняет LibreOffice, поэтому абсолютное совпадение с Word или
экспортируемым PDF не гарантируется. Стандартные шрифты берутся из Windows.
Длинные документы, таблицы, колонтитулы, история и экспорт требуют ручной
проверки перед выпуском. В рамках этой замены приложение и тесты не запускались.

## Сборка

Нужны Node.js 22+ и .NET 10 SDK. MSBuild автоматически подготавливает локальные
ресурсы. Отдельно их можно собрать:

```powershell
cd web/word
npm ci --no-audit --no-fund
npm run build
```

Результат — `src/ObsidianDocs/WordAssets`, копируется в сборку и установщик.
Node.js нужен только для сборки. Для работы нужен **Microsoft Edge WebView2
Runtime**; если его нет, приложение показывает сообщение вместо редактора.
Этот runtime пока не добавлен в автономный установщик.

Все JS/CSS поставляются локально. Внешние сетевые запросы, загрузки и новые
окна WebView заблокированы, telemetry отключена. Документ передаётся в памяти
через локальный обработчик WebResourceRequested, без HTTP-сервера и загрузки
на сторонние сервисы. Данные профиля WebView находятся в
`%LOCALAPPDATA%/ObsidianDocs/WordWebView`.

## Лицензирование перед публичным выпуском

SuperDoc **1.47.2** — AGPL-3.0. Более новая ветка 2.x с отдельно лицензированным
закрытым DOCX Engine здесь не используется. Исходники проекта:
https://github.com/superdoc/docx-editor. Версия зависимости зафиксирована в
package.json и package-lock.json. В этой сборке vendor JS содержит описанный
выше патч подготовки разметки; изменение отмечено в уведомлениях сборки.

Полные исходники движка и наши изменения подготовлены в отдельном архиве:
[состав и сборка](../../packaging/superdoc/SOURCE-INFO.md). В него входят точный
снимок исходников, опубликованный npm-пакет, содержимое source map, изменённый
PresentationEditor.ts и оболочка ObsiDopf. patch-engine-source.mjs позволяет
пересобирать изменённый движок из TypeScript/Vue; build.mjs --engine-dist принимает
такой bundle вместо штатного пакета npm. Последующая инкрементальная .NET-сборка
сохраняет явно подготовленные WordAssets до следующего npm run build.

Установщик и оба архива исходников публикуются для одной версии проекта.
`packaging/collect-npm-notices.mjs` собирает лицензии точных версий из npm lock-файла
и source map vendor JS. Полученные тексты и сведения об источниках находятся
в `packaging/notices/npm` и включаются в `ThirdPartyNotices` установщика.
Верхняя кнопка § открывает окно лицензий в приложении.
